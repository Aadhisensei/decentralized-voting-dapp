🎓 Viva Preparation Notes — VoteChain DApp

1. PROJECT OVERVIEW (30-second pitch)

"VoteChain is a decentralized voting application built on the Ethereum blockchain. It allows an admin to add candidates, and any user with a MetaMask wallet can cast one vote. All votes are stored on the Sepolia testnet, making them transparent, immutable, and verifiable. The smart contract is written in Solidity, the frontend uses HTML/CSS/JavaScript with ethers.js to interact with the blockchain."

3. SMART CONTRACT EXPLAINED (line by line)

File: contracts/Voting.sol

// SPDX-License-Identifier: MIT

What: License identifier. MIT means open source. Why: Solidity compiler gives a warning if this is missing.

pragma solidity ^0.8.19;

What: Specifies the compiler version. Why: ^0.8.19 means "0.8.19 or higher but below 0.9.0". Version 0.8+ has built-in overflow protection.

Data Structures

struct Candidate {
    uint256 id;
    string name;
    uint256 voteCount;
}

What: A custom data type that groups related data together. Why: Each candidate has an ID, a name, and a vote count.

address public owner;

What: Stores the wallet address of whoever deployed the contract. Why: Only the owner can add candidates. public auto-generates a getter function.

uint256 public candidateCount;

What: Counter that tracks how many candidates exist. Why: Used as the ID for the next candidate and to loop through all candidates.

mapping(uint256 => Candidate) public candidates;

What: A key-value store. Maps a candidate ID (number) to a Candidate struct. Why: Allows lookup of any candidate by ID. Like a dictionary/hashmap.

mapping(address => bool) public hasVoted;

What: Maps a wallet address to true/false. Why: Tracks whether an address has already voted. Prevents double voting.

Events

event CandidateAdded(uint256 indexed candidateId, string name);
event Voted(address indexed voter, uint256 indexed candidateId);

What: Events are logs stored on the blockchain. Why: The frontend listens for these events to auto-refresh the UI when something changes. indexed makes them searchable/filterable.

Modifier

modifier onlyOwner() {
    require(msg.sender == owner, "Only the contract owner can perform this action");
    _;
}

What: A reusable check that runs before a function. Why: msg.sender is the address calling the function. If it's not the owner, the transaction reverts. The _; placeholder is where the actual function body runs.

Constructor

constructor() {
    owner = msg.sender;
}

What: Runs once when the contract is deployed. Why: Sets the deployer's address as the owner. This can never be changed afterward.

Functions

addCandidate()

function addCandidate(string calldata _name) external onlyOwner {
    require(bytes(_name).length > 0, "Candidate name cannot be empty");
    candidateCount++;
    candidates[candidateCount] = Candidate(candidateCount, _name, 0);
    emit CandidateAdded(candidateCount, _name);
}
  • external — can only be called from outside the contract (saves gas vs public)
  • onlyOwner — modifier restricts access to the contract owner
  • calldata — read-only memory location, cheapest for external function string parameters
  • require — validates input, reverts if name is empty
  • Increments candidateCount, creates a new Candidate with 0 votes, emits an event

vote()

function vote(uint256 _candidateId) external {
    require(!hasVoted[msg.sender], "You have already voted");
    require(_candidateId > 0 && _candidateId <= candidateCount, "Invalid candidate ID");
    hasVoted[msg.sender] = true;
    candidates[_candidateId].voteCount++;
    emit Voted(msg.sender, _candidateId);
}
  • No onlyOwner — anyone can vote
  • First require — checks the caller hasn't voted before
  • Second require — validates the candidate ID exists
  • Marks the address as voted BEFORE incrementing (prevents reentrancy)
  • Increments vote count and emits event

getCandidate()

function getCandidate(uint256 _candidateId) external view returns (uint256, string memory, uint256) {
  • view — read-only function, doesn't modify state, costs NO gas when called from frontend
  • returns — sends back the candidate's id, name, and vote count
  • memory — temporary storage for the string return value

getCandidateCount()

function getCandidateCount() external view returns (uint256) {
    return candidateCount;
}
  • Simple getter to know how many candidates exist
  • Used by the frontend to loop through all candidates

Architecture (Data Flow)

Step 1: Configuration (Lines 1-19)

const SEPOLIA_CHAIN_ID = "0xaa36a7";
const CONTRACT_ABI = [
  "function owner() view returns (address)",
  "function vote(uint256) external",
  // ... more function signatures
];
  • CONTRACT_ADDRESS — The deployed contract's address on Sepolia blockchain. This tells ethers.js WHERE to send transactions.
  • SEPOLIA_CHAIN_ID — Hexadecimal chain ID for Sepolia (11155111 in decimal). Used to verify the wallet is on the correct network.
  • CONTRACT_ABI — The Application Binary Interface. It lists every function the contract has, their parameters, and return types. ethers.js uses this to encode/decode data when talking to the contract.

Step 2: Wallet Connection (Lines 80-150)

// Check if MetaMask is installed
if (!window.ethereum) { alert("MetaMask not installed!"); return; }

// Request wallet access
const accounts = await window.ethereum.request({ method: "eth_requestAccounts" });
  • window.ethereum is injected by MetaMask into every webpage
  • eth_requestAccounts triggers the MetaMask popup asking permission to connect
// Create provider and signer
provider = new ethers.BrowserProvider(window.ethereum);
signer = await provider.getSigner();
  • Provider = read-only connection to the blockchain (can query data)
  • Signer = a provider + the ability to sign transactions (can write data)
// Network validation
const network = await provider.getNetwork();
if ("0x" + network.chainId.toString(16) !== SEPOLIA_CHAIN_ID) {
  await window.ethereum.request({
    method: "wallet_switchEthereumChain",
    params: [{ chainId: SEPOLIA_CHAIN_ID }],
  });
}
  • Checks if MetaMask is on Sepolia
  • If not, automatically requests MetaMask to switch networks
// Create contract instance
contract = new ethers.Contract(CONTRACT_ADDRESS, CONTRACT_ABI, signer);
  • Combines the address + ABI + signer into a contract object
  • Now contract.vote(1) will automatically encode the call, send it via MetaMask, and return the result
// Check if connected user is the contract owner
const ownerAddr = await contract.owner();
if (ownerAddr.toLowerCase() === userAddress.toLowerCase()) {
  ownerPanel.classList.remove("hidden");
}
  • Calls the owner() view function (free, no gas)
  • Compares with the connected wallet address
  • Shows the Admin Panel only to the owner

Step 3: Loading Candidates (Lines 152-230)

const count = Number(await contract.getCandidateCount());
for (let i = 1; i <= count; i++) {
  const [id, name, voteCount] = await contract.getCandidate(i);
  candidates.push({ id: Number(id), name, votes: Number(voteCount) });
}
  • Calls getCandidateCount() to know how many candidates exist
  • Loops through each candidate ID and calls getCandidate(i)
  • These are all view function calls, so they are FREE (no gas, no MetaMask popup)
  • Results are used to build the HTML candidate cards dynamically

Step 4: Casting a Vote (Lines 232-246)

async function castVote(candidateId) {
  const tx = await contract.vote(candidateId);  // Sends transaction
  await tx.wait();                                // Waits for block confirmation
  await loadCandidates();                         // Refreshes the UI
}
  • contract.vote(candidateId) — ethers.js encodes this into a transaction, MetaMask signs it, and broadcasts it to Sepolia
  • tx.wait() — waits until the transaction is mined (included in a block, ~12 seconds)
  • After confirmation, reloads all candidates to show updated vote counts

Step 5: Adding a Candidate (Lines 248-272)

const tx = await contract.addCandidate(name);
await tx.wait();
  • Same pattern as voting: send transaction → wait for confirmation → refresh UI
  • This call will FAIL if the caller is not the owner (the onlyOwner modifier in Solidity will revert it)

Step 6: Event Listeners (Lines 143-145, 288-291)

// Blockchain events (auto-refresh when something happens on-chain)
contract.on("CandidateAdded", () => loadCandidates());
contract.on("Voted", () => loadCandidates());

// MetaMask events (reload page if account or network changes)
window.ethereum.on("accountsChanged", () => window.location.reload());
window.ethereum.on("chainChanged", () => window.location.reload());
  • The contract emits events when candidates are added or votes are cast
  • ethers.js subscribes to these events and triggers a callback
  • If the user switches wallets or networks in MetaMask, the page reloads to reflect the new state

6. KEY CONCEPTS TO KNOW

What is a Smart Contract?

A program stored on the blockchain that automatically executes when conditions are met. Once deployed, it cannot be modified. It runs on every node in the network.

What is Solidity?

A statically-typed, contract-oriented programming language designed for the Ethereum Virtual Machine (EVM). Syntax is similar to JavaScript/C++.

What is Gas?

The unit of computation on Ethereum. Every operation (storing data, computing) costs gas. Users pay gas fees in ETH to incentivize miners/validators to process transactions.

What is a Testnet?

A separate blockchain network that mimics the main Ethereum network but uses worthless test ETH. Used for testing without spending real money. Sepolia is one of the main Ethereum testnets.

What is MetaMask?

A browser extension that acts as an Ethereum wallet. It stores private keys, signs transactions, and connects DApps to the blockchain.

What is ABI?

Application Binary Interface. A JSON description of the contract's functions and events. The frontend needs it to know how to encode function calls and decode responses.

What is ethers.js?

A JavaScript library that provides tools to interact with the Ethereum blockchain. It handles connecting to nodes, encoding transactions, and calling smart contract functions.

What is a Mapping?

A key-value data structure in Solidity (like a hashmap). mapping(address => bool) maps wallet addresses to boolean values. All keys exist by default (unset values return the default: false for bool, 0 for uint).

What is msg.sender?

A global variable in Solidity that holds the address of whoever is calling the current function.

What is require()?

A function that checks a condition. If the condition is false, the entire transaction reverts (undoes all changes) and returns the error message. Used for input validation and access control.

View vs Pure functions?

  • view — reads blockchain state but doesn't modify it. Free to call externally.
  • pure — doesn't read or modify state. Used for utility calculations.

What is an Event in Solidity?

Events are logs emitted by the contract and stored on the blockchain. They are cheap to emit and can be listened to by frontend applications. They cannot be read by other contracts.

What is a Modifier?

A reusable piece of code that runs before (or after) a function. onlyOwner checks that the caller is the contract owner before allowing the function to execute.

7. LIKELY VIVA QUESTIONS AND ANSWERS

About the Project

Q: What is this project about? A: It's a decentralized voting application where users connect their MetaMask wallet and vote for candidates. All votes are stored immutably on the Ethereum Sepolia testnet using a Solidity smart contract.

Q: Why did you choose a voting DApp? A: Voting benefits most from blockchain because it requires transparency, immutability, and trust. Traditional voting systems rely on a central authority, while this removes that need entirely.

Q: What problem does this solve? A: Traditional voting can be tampered with by centralized authorities. This DApp makes every vote publicly verifiable on the blockchain while maintaining voter pseudonymity through wallet addresses.

Q: Can this be used in real elections? A: This is a proof-of-concept on a testnet. For real elections, it would need identity verification (KYC), scalability improvements, gas optimization, and possibly a Layer 2 solution to reduce costs.

About the Smart Contract

Q: Explain the smart contract structure. A: The contract has a Candidate struct, two mappings (candidates and hasVoted), an owner variable, and four main functions: addCandidate (owner-only), vote (public), getCandidate (read-only), and getCandidateCount (read-only).

Q: How do you prevent double voting? A: The hasVoted mapping stores true for any address that has voted. The vote() function checks require(!hasVoted[msg.sender]) before allowing the vote. If someone tries to vote again, the transaction reverts.

Q: Why use external instead of public? A: external functions can only be called from outside the contract, not internally. They are slightly cheaper in gas because they can read calldata directly instead of copying it to memory.

Q: What is calldata vs memory? A: calldata is a read-only, non-modifiable area where function arguments are stored. It's cheaper than memory for external functions. memory is a temporary read-write area that exists only during function execution.

Q: Why is the owner set in the constructor? A: The constructor runs exactly once during deployment. msg.sender in the constructor is the deployer's address, so they become the permanent owner.

Q: Can the owner be changed? A: No. There's no function to transfer ownership. Once deployed, the owner is fixed forever.

Q: What happens if someone sends ETH to this contract? A: The transaction would fail because there's no receive() or fallback() function. The contract doesn't handle ETH transfers.

Q: What is the indexed keyword in events? A: indexed parameters are stored in the event's "topics" (a special data structure), making them filterable/searchable. Up to 3 parameters can be indexed per event.

About the Frontend

Q: How does the frontend connect to the blockchain? A: The frontend uses ethers.js to connect to MetaMask via window.ethereum. MetaMask acts as the provider (connection to Sepolia) and the signer (signs transactions with the private key).

Q: What is the ABI and why is it needed? A: The ABI (Application Binary Interface) defines the contract's functions, their parameters, and return types. ethers.js uses it to encode function calls into the binary format the EVM understands.

Q: How does the frontend know when a vote happens? A: It listens for the Voted event using contract.on("Voted", callback). When the event is emitted on-chain, the callback triggers and reloads the candidate list.

Q: What's the difference between reading and writing to the contract? A: Read operations (view/pure functions like getCandidate) are free and don't need MetaMask confirmation. Write operations (like vote, addCandidate) modify blockchain state, cost gas, and require MetaMask to sign the transaction.

Q: Why use ethers.js instead of web3.js? A: ethers.js is lighter, has better TypeScript support, separates the Provider (read) and Signer (write) concepts cleanly, and is generally considered more modern and developer-friendly.

About Blockchain & Ethereum

Q: What is a blockchain? A: A distributed, immutable ledger that records transactions across many computers. No single entity controls it. Data once written cannot be altered without consensus from the network.

Q: What is Ethereum? A: A decentralized platform that runs smart contracts. Unlike Bitcoin (which only handles currency), Ethereum allows arbitrary programs to run on the blockchain through the EVM.

Q: What is EVM? A: Ethereum Virtual Machine. It's the runtime environment for smart contracts. Every Ethereum node runs the EVM to execute contract code and reach consensus on the state.

Q: What is a transaction? A: A signed message sent from one account to another. It can transfer ETH, deploy a contract, or call a contract function. Every transaction costs gas and is permanently recorded.

Q: What is a block? A: A bundle of transactions grouped together. Blocks are added to the chain approximately every 12 seconds on Ethereum. Each block references the previous block, forming the chain.

Q: What is gas and gas fees? A: Gas measures the computational work of a transaction. The gas fee = gas used × gas price. Users pay gas fees in ETH to validators who process the transaction. This prevents spam and infinite loops.

Q: What is the difference between mainnet and testnet? A: Mainnet uses real ETH with real value. Testnet (like Sepolia) uses free test ETH with no value. Developers use testnets to test their DApps before deploying to mainnet.

Q: What is a wallet address? A: A 42-character hexadecimal string (starting with 0x) derived from the public key. It identifies an account on Ethereum. Example: 0x5ef786300ADB12516801513885C193e25ec58cDd

Q: What is a private key? A: A secret 256-bit number that proves ownership of a wallet. It's used to sign transactions. Anyone with the private key has full control of that wallet. It should never be shared.

Q: What is Hardhat? A: A development environment for Ethereum. It compiles Solidity code, runs tests, deploys contracts, and provides a local blockchain for testing.

Tricky Questions

Q: Is this truly decentralized? A: The smart contract is decentralized (runs on Ethereum nodes). However, the frontend is centralized (hosted on a server/GitHub Pages). A fully decentralized version would host the frontend on IPFS.

Q: What are the limitations of this DApp? A: (1) No voter identity verification — anyone can create multiple wallets. (2) Candidates can't be removed. (3) Voting can't be paused or ended. (4) Gas fees for each vote. (5) Frontend is centralized.

Q: How would you improve this project? A: Add a voting deadline (using block.timestamp), implement voter registration/whitelisting, add ability to end the election, host the frontend on IPFS, add candidate descriptions, and implement a delegate voting system.

Q: What is a reentrancy attack? A: When a contract calls an external contract, and that external contract calls back into the original contract before the first call finishes. In the vote() function, the state (hasVoted = true) is updated BEFORE any external interaction, which prevents reentrancy.

Q: Why Sepolia and not Goerli? A: Goerli has been deprecated. Sepolia is the recommended testnet for DApp development as of 2024+.
